# הושעיה אמן בלונים — מערכת ניהול

אפליקציה חד-קובצית (`index.html`) — קטלוג עיצובים, העלאת תמונות, הצעות מחיר, רישום לקוחות וניהול מלאי.

**חי ב:** https://hos100345.github.io/hoshaya-quotes/ (GitHub Pages מ-`main`)

## מחירון
`PL` ב-`index.html` — 36 פריטים בשתי משפחות: **חנות** (12) ו**עיצוב אירועים** (24).
`b` מחיר · `u` יחידה · `c` קטגוריה · `n` הערה. אין מחיר-תושב לפריט.

**כללי התמחור (לא לשבור):**
- `LOCAL_PCT` = 10% הנחת תושב יישוב, **על עיצוב אירועים בלבד** — לא על החנות
  ולא על נסיעות. לכן ההנחה יורדת מסכום פריטי האירועים ולא מוטבעת במחיר הפריט.
- `TRAVEL_RATE` = 2 ₪ לק"מ הלוך ושוב · `MIN_CALLOUT` = 650 ₪, ובחנות אין מינימום,
  ולכן ההתראה נבדקת מול סכום האירועים בלבד וכשיש נסיעה בפועל.
- **`qTotals()` הוא החישוב היחיד.** המסך, הודעת הוואטסאפ, דרישת התשלום והיומן
  קוראים לו. קודם כל אחד חישב לעצמו, ותעריף או בסיס הנחה שהשתנו פילגו ביניהם
  בלי שאף אחד ישים לב.
- **שם פריט עם גרש כפול חייב `escHtml` ב-`value`.** `18"` חתך את ה-value באמצע,
  ולכן בחירת הפריט החזירה שם שלא קיים ב-`PL` והמחיר יצא 0 בלי שום הודעה.

## כינויים במחירון (`a`)
פריט יכול לשאת `a:[...]` — איך לקוחות באמת אומרים אותו. למשל `מיילר 5" + בסיס`
נקרא בשיחה "מספרים קטנים עם בסיס".

- הכינויים נשלחים ל-AI בתוך `priceListText()` כשורת `נקרא גם:`, יחד עם הוראה
  מפורשת להחזיר את **השם שלפני הנקודתיים**. בלי ההוראה הזו המודל עלול להחזיר
  את הכינוי כשם הפריט, `PL` לא ימצא אותו והמחיר יוצא 0 — בשקט.
- אותם כינויים נתפסים גם בחיפוש בבורר הידני.
- זה חי בצד לקוח בלבד. אין צורך ב-redeploy של `ai-gateway` כדי להוסיף כינוי.

## הצעת מחיר — בחירת פריט
`🔎 בחר פריט מהמחירון` פותח בורר עם חיפוש (שם פריט או קטגוריה), מקובץ לקטגוריות
ומציג מחיר ויחידה לכל שורה. `+ שורה ריקה` נשאר לרשימה הנפתחת הרגילה.

- הרשימה הנפתחת לבדה לא הספיקה מרגע ש-37 פריטים נכנסו למחירון.
- פריט שכבר בהצעה מעלה כמות במקום לפתוח שורה כפולה.
- `qRowHTML()` הוא המקור היחיד לשורת פריט. הוא היה משוכפל ב-`qadd` וב-`qapply`,
  ושינוי בשורה היה נכנס רק לאחד מהם.
- **`data-pk` ולא `onclick`** — שם פריט מכיל גרש כפול. אותה מלכודת, שלישית.
- **`getElementById` ולא `querySelector` ל-`QR<id>`**: id של שורה שנוצרה מניתוח AI
  הוא `Date.now()+Math.random()` ומכיל נקודה, ש-`querySelector` קורא כמחלקה.

## מלאי — סינון
מעל רשימת הפריטים: קטגוריה ← גודל ← חיפוש חופשי.

- **הגודל נגזר מהשם** (`invSizeOf`) ולא מעמודה ב-DB: `34"` · `12 אינץ'` · `260Q`.
  הוספת עמודת גודל הייתה דורשת לתייג מחדש את כל המלאי הקיים, והשם כבר מחזיק
  את המידע. המשמעות: פריט ששמו בלי גודל נופל ל"ללא גודל" — לא נעלם.
- שורת הגדלים מופיעה רק כשנבחרה קטגוריה ויש בה יותר מגודל אחד.
- קטגוריה בלי גודל נבחר → הרשימה מוצגת **מחולקת לגדלים**. 30 בלוני ספרות
  ברשימה שטוחה אחת הם בדיוק המקרה שבגללו זה נבנה.
- **צ'יפ הגודל עובר בהאצלה (`data-sz`) ולא ב-`onclick`.** `34"` בתוך תכונת HTML
  נחתך באמצע — אותה מלכודת שכבר נשרפנו בה ברשימת פריטי המחירון.
- החיפוש עובר דרך `normName`, שמסיר גרשיים, ולכן `34` מוצא גם `34"`.

## מבנה
- `index.html` — האפליקציה כולה. ללא build step, ללא framework.
- `supabase/functions/ai-gateway/index.ts` — שער ה-AI. מחזיק את המפתחות בצד שרת.

## AI — הכול דרך Supabase Edge Function `ai-gateway`
| פעולה | שימוש באפליקציה | מנוע |
|---|---|---|
| `health` | אבחון (פתוח, בלי טוקן) | — |
| `chat` | ניתוח שיחת וואטסאפ מודבקת → הצעת מחיר | Claude |
| `inventory` | הדבקת רשימת מלאי → שורות מובנות | Claude |
| `vision` | זיהוי קטגוריה לתמונה שמועלית לקטלוג | Claude |
| `audio` | תמלול הקלטת שיחה → הצעת מחיר | Gemini לתמלול, Claude לחילוץ |

**אימות:**
```
curl -X POST https://sccivxenkyzxolpraexf.supabase.co/functions/v1/ai-gateway \
  -H 'Content-Type: application/json' -d '{"action":"health"}'
```
מחזיר גרסה, מודל, ואילו מפתחות קיימים (בלי הערכים).

עם `{"action":"health","probe":"gemini"}` הוא גם שואל את גוגל אילו מודלים
המפתח באמת מקבל — `ListModels` בלבד, בלי יצירת תוכן ובלי עלות. זו הדרך לענות
על "איזה מודל לשים ב-`GEMINI_MODELS`" בלי לנחש, ולאמת שהמפתח תקף.

### כללים שנלמדו
- **`verify_jwt=false` כאן הוא מכוון**, כדי ש-`health` יהיה ניתן לאבחון ב-curl.
  כל פעולה אחרת מאמתת בעצמה: טוקן Supabase + אימייל מול `ADMIN_EMAILS`.
  בלי טוקן — 401.
- **הפרונט חייב להיות מחובר ל-Supabase** (אותה התחברות של טאב המלאי) כדי
  שה-AI יעבוד. בלי זה מוצגת הודעה שמפנה לטאב המלאי, לא כשל סתום.
- **אין `zodOutputFormat`.** ה-subpath `@anthropic-ai/sdk/helpers/zod` לא נפתר
  ב-runtime של Supabase והפונקציה לא עולה בכלל (`worker boot error, path not
  found`). במקומו: המודל מתבקש JSON, והתשובה עוברת `coerce` בקוד — שגם מנרמל
  תאריך, כמויות וקטגוריות.
- **לא לקחת `content[0]`.** עם thinking אדפטיבי הבלוק הראשון עשוי להיות
  `thinking`. `textOf()` סורק אחרי הבלוק מסוג `text`.
- **תמלול דורש Gemini.** ה-Messages API של Claude לא מקבל קלט אודיו. אם אין
  מפתח Gemini ב-Secrets, `audio` מחזירה 501 עם הסבר — לא כשל עמום.
- **רשימת מודלי Gemini היא העדפה, לא הסתמכות.** גוגל מוציאה מודלים משימוש מדי
  כמה חודשים — `gemini-1.5-flash` נעלם וזה מה שהשבית את התמלול בפעם הקודמת.
  אם כל הרשימה הקשיחה נעלמה, הקוד שואל את גוגל מה קיים היום ובוחר flash.
  שגיאה שאינה "המודל לא קיים" (מפתח שגוי, מכסה, קובץ פסול) עוצרת מיד ולא
  מבזבזת ניסיונות.
- **Edge Functions לא נפרסות מגיט.** מיזוג PR שנוגע ב-`supabase/functions/`
  לא מעלה כלום לאוויר; צריך `deploy_edge_function` מפורש.
- **ה-Worker ב-Cloudflare פרש.** הוא דרש deploy ידני, ושם נשאר קוד שקרא למודל
  שגוגל הוציאה משימוש — ולכן הדבקת השיחה והתמלול לא עבדו בפועל. Supabase
  נפרס מכאן והמפתחות כבר שם.

## מלאי — Supabase הוא מקור האמת
המלאי נקרא ונכתב מול `inventory.items` בפרויקט `sccivxenkyzxolpraexf`.
**localStorage לא משמש למלאי.** כל פלוס/מינוס, הוספה, עריכה וייבוא נכתבים לשרת.

- כניסה: Supabase Auth, קישור למייל. הגישה נעולה ב-RLS על `hoshaya@gmail.com` בלבד.
- קטגוריות: לטקס / מיילר / טוויסטינג / הליום / אביזרים / אחר — נאכף ב-CHECK על הטבלה.
- כל שינוי כמות נרשם אוטומטית ב-`inventory.movements` ע"י טריגר.
  האפליקציה כותבת `updated_by='אפליקציה'`, והטריגר לוקח משם את `source`.
- הקטלוג (תמונות) יושב ב-Google Drive, לא ב-localStorage.

"📥 ייבוא" מקבל רשימה חופשית (AI מסדר) או JSON מוכן, ותמיד מציג אישור לפני שכותב לשרת.
"📤 העתק את המלאי הנוכחי" מייצא JSON שאפשר לשלוח ולקבל בחזרה מעודכן.

תיקיית השורש: **📸 תמונות עבודות**, מזהה קבוע `176FEefUBgllY3xB5AOGgGq1yW0o_pJkr`
(תחת "🎈 הושעיה אמן בלונים"). 19 תת-התיקיות שבה הן הקטגוריות באפליקציה.

- **האפליקציה לא משנה את מבנה הדרייב**: לא יוצרת תיקיות, לא משנה שמות, לא מזיזה
  ולא מוחקת. הפעולה היחידה שכותבת היא העלאת קובץ חדש לתיקייה קיימת שנבחרה.
- מסוננים לפי mimeType — תמונות ווידאו בלבד. PDF ומסמכי Google בשורש לא מוצגים.
- וידאו לעולם לא נטען כתמונה: מוצגת התמונה הממוזערת שדרייב הכין עם סמן ▶,
  ואם אין — אריח 🎬. לחיצה פותחת את הקובץ בדרייב במקום להוריד אותו.
- HEIC מהאייפון עובד — דרייב מייצר לו תמונה ממוזערת.
- שורת מונה מעל הגלריה מציגה כמה פריטים וכמה קטגוריות נטענו בפועל.

## התקנה כאפליקציה (PWA)
`manifest.webmanifest` + `sw.js` + `icons/` — האתר ניתן להתקנה במסך הבית.

- אייקון בלון, נוצר בקוד (`icons/*.png`, 192/512 + maskable + apple-touch).
- ה-service worker **לא** מכניס את ה-HTML למטמון מראש: ניווט הוא network-first,
  אחרת פריסה חדשה של Pages הייתה מוגשת מגרסה ישנה.
- נכסים סטטיים בלבד נשמרים במטמון. דרייב, Supabase וגופנים עוברים ישר לרשת.
- שינוי ב-`sw.js` מחייב העלאת `VERSION` בראש הקובץ כדי לנקות מטמון ישן.

## שליחת תמונה בוואטסאפ
מלחיצה על תמונה בקטלוג נפתח מסך שליחה: מספר טלפון, הודעה, ושלושה מסלולים.

⚠️ **אי אפשר לצרף קובץ לוואטסאפ דרך קישור.** `wa.me` נושא טקסט בלבד,
ו-`navigator.share` מצרף קובץ אבל לא מקבל נמען. אין דרך לעשות את שניהם בבת אחת —
זו מגבלה של וואטסאפ ומערכת ההפעלה, לא של הקוד. לכן:

| מסלול | נמען | תמונה |
|---|---|---|
| "פתח וואטסאפ עם המספר" | מדויק | מועתקת ללוח, מדביקים בשיחה |
| "שתף את התמונה" | נבחר ידנית בגיליון | מצורפת אוטומטית |
| "הורד למכשיר" | — | קובץ מקומי |

הלוח מקבל PNG בלבד, אז התמונה מומרת דרך canvas. HEIC לא נפתח בכרום ולכן
ההעתקה תיכשל שם, והמסך יפנה למסלול השיתוף.
